# ADR-001: Жобаны жеткізу моделін таңдау

**Күйі:** Қабылданды  
**Жоба:** IT-жобаның талаптарын басқару

## 1. Контекст

Жобаның мақсаты — IT-жоба шеңберінде талаптарды жинау, талдау,
құжаттау, басымдықтарын анықтау және талаптарға енгізілетін
өзгерістерді басқару процесін ұйымдастыру.

Жоба барысында пайдаланушылардың қажеттіліктері мен талаптары
өзгеруі мүмкін. Сондықтан жобаны бірден толық орындаудан гөрі,
кезең-кезеңімен дамыту және әр кезеңнен кейін нәтижені тексеру қажет.

Осыған байланысты жобаға сәйкес келетін жеткізу моделін таңдау керек.

## 2. Қарастырылған нұсқалар

### Нұсқа 1 — Waterfall

Waterfall моделінде жобаның талаптары алдын ала анықталып,
жұмыстар белгіленген кезеңдер бойынша ретімен орындалады.

Артықшылықтары:
- жобаны алдын ала жоспарлау оңай;
- кезеңдер мен мерзімдер нақты анықталады;
- құжаттаманы жүргізу ыңғайлы.

Кемшіліктері:
- талаптарды кейін өзгерту күрделі;
- пайдаланушыдан кері байланыс кеш алынуы мүмкін;
- өзгерістер енгізу қосымша уақыт пен шығын талап етеді.

### Нұсқа 2 — Agile / Scrum

Agile / Scrum кезінде жоба қысқа итерациялар арқылы орындалады.
Әр итерациядан кейін нәтиже бағаланып, талаптар нақтыланады.

Артықшылықтары:
- өзгеретін талаптарға жылдам бейімделуге болады;
- пайдаланушылардан тұрақты кері байланыс алынады;
- талаптарды backlog арқылы басқаруға болады;
- MVP нұсқасын ертерек жасауға мүмкіндік береді.

Кемшіліктері:
- backlog-ты тұрақты жаңарту қажет;
- команда мүшелері арасында тұрақты коммуникация керек;
- өзгерістерді дұрыс басқармаған жағдайда жоба көлемі ұлғаюы мүмкін.

### Нұсқа 3 — Hybrid

Hybrid моделі Waterfall және Agile тәсілдерін біріктіреді.

Артықшылықтары:
- жобаның жалпы жоспарын алдын ала анықтауға болады;
- кейбір жұмыстарды Agile тәсілімен итерациялық орындауға болады.

Кемшіліктері:
- жобаны басқару күрделене түседі;
- екі тәсілді дұрыс үйлестіру қажет.

## 3. Қабылданған шешім

Жоба үшін **Agile / Scrum** моделі таңдалды.

Негізгі себеп — жобаның талаптарды басқаруға бағытталуы.
IT-жобада талаптар өзгеруі немесе нақтылануы мүмкін.
Agile / Scrum талаптарды backlog-та сақтауға, олардың
басымдықтарын өзгертуге және әр итерацияда нәтижені тексеруге
мүмкіндік береді.

## 4. Шешімнің салдары

Оң салдары:
- талаптардың өзгеруіне жылдам жауап беру;
- пайдаланушылардан тұрақты кері байланыс алу;
- MVP нұсқасын ертерек дайындау;
- тапсырмаларды backlog арқылы бақылау;
- жобаны кезең-кезеңімен дамыту.

Теріс салдары:
- backlog-ты тұрақты жаңарту қажет;
- команда мүшелерінің тұрақты коммуникациясы керек;
- өзгерістерді бақылау қажет;
- талаптардың бақылаусыз өсу қаупі бар.

## 5. Қабылданбаған нұсқалар

**Waterfall** — өзгеретін талаптарға бейімделу мүмкіндігі төмен
болғандықтан қабылданбады.

**Hybrid** — осы оқу жобасының көлемі үшін басқару процесін
қажетсіз күрделендіретіндіктен қабылданбады.
